How to run this site

How to set up this website, change it, and put your changes online. You don’t need to know how to code. You just need to type what you’re told and read what comes back.

Two tools, two columns. This guide covers two tools: Claude Code and Codex. They both do the same job, so pick one. Claude Code is in the left box, Codex is in the right box. Only follow your one. On a phone the boxes go one above the other, so check the coloured name at the top of each box.

1. What this site is

Three things work together to make this website. Here’s what each one does.

The files. This website is just a folder of files. Each page is one file. The page you’re reading right now is a file called howto/index.html. That’s all a website is.

GitHub. A website that holds those files for you. It also saves a copy of every change anyone has ever made. That means nothing you do is forever. You can always go back.

Your files live here: github.com/thirstypig/rhyschang

GitHub Pages. A free service that takes your files and puts them on the internet at rhyschang.com. When your files change, it updates the website by itself. It usually takes less than a minute.

So the whole job is: change a file → send it to GitHub → wait a minute. Everything below is a version of those three steps.

2. Setting up (you only do this once)

This is the longest part. You only do it one time, ever. After this, changing something takes about two minutes.

Step 1

Get a GitHub account

Go to github.com/signup and make an account. You’ll need an email you can check, because they send you a code.

Then tell Uncle Jimmy your GitHub username. He’ll add you to the site’s files. You’ll get an email with a button that says Accept invitation. Click it.

Until you click that, you can look at the files but you can’t change them.

Step 2

Open the Terminal

The Terminal is an app where you type instead of clicking. It looks scary. It isn’t.

On a Mac: hold Command and press Space. Type Terminal. Press Enter. A window opens with a blinking cursor.

On Windows: search for Terminal in the Start menu.

From now on, when this guide says “type this,” it means type it in that window and press Enter.

Step 3

Install your tool

First you need a program called Node. Go to nodejs.org, download the one it suggests, and install it like any other app.

Then come back to the Terminal and type the line for your tool:

Claude Code

npm install -g @anthropic-ai/claude-code

If that line ever stops working, the real instructions are at docs.claude.com.

Codex

npm install -g @openai/codex

If that line ever stops working, the real instructions are at developers.openai.com.

If you get a bunch of red text that says permission denied or EACCES, nothing is broken. Your computer just blocked it. Show it to Uncle Jimmy — it’s a normal setup problem and it’s quick to fix.

Step 4

Sign in

Start your tool for the first time. It opens a web page and asks you to log in. Each tool needs its own paid account, so check with Uncle Jimmy about which one you have.

Claude Code

claude

Log in with your Claude account.

Codex

codex

Log in with your ChatGPT account.

Step 5

Copy the website onto your computer

Type these two lines, one at a time:

cd ~/Documents
git clone https://github.com/thirstypig/rhyschang.git

The first line moves you into your Documents folder. The second one downloads the whole website into a new folder called rhyschang.

Now go inside that folder:

cd ~/Documents/rhyschang

You’ll type that last line every time you work on the site.

That’s setup done. You never have to do this part again.

3. Changing something for the first time

Let’s change one line and put it on the internet.

Step 1

Go to the folder, then start your tool

Claude Code

cd ~/Documents/rhyschang
claude

Codex

cd ~/Documents/rhyschang
codex

Starting the tool inside the folder is important. That’s how it knows which files you’re talking about.

Step 2

Ask for what you want, in normal words

Type this and press Enter. It’s the same for both tools:

On the home page, change the line that says “This is my website” to say something about me instead.

The tool finds the file, shows you what it wants to change, and asks if that’s okay. Read it. If it looks right, say yes.

Step 3

Put it online

Right now your change is only on your own computer. To put it on the internet, ask:

Save this change and publish it to the website.

The tool does the rest. Wait about a minute, then go to rhyschang.com. Your change is there.

If the page looks the same, don’t worry. Web browsers save old copies of pages. Hold Shift and click reload to get a fresh one. If it’s still old, wait one more minute. The site takes a moment to update.

4. What those three words mean

When you said “publish,” three things happened. You don’t have to remember them. But knowing the words makes error messages a lot easier to read later.

Commit means your change got saved, with a little note about what you changed. All of these are kept, so you can always go back to an older one.

Push means that saved change got sent from your computer up to GitHub.

Build means GitHub saw the new files and updated the website. This is the part that takes about a minute.

When something goes wrong, it’s almost always one of these three — and the error message will tell you which one.

5. Adding a new page

Say you want a page at rhyschang.com/music. Just ask:

Add a new page at /music. Make it look like the pages I already have, and put a link to it on the home page.

What happens behind the scenes: it makes a folder called music with a file called index.html inside it. That’s the trick to getting a short web address. A folder named music with index.html inside becomes /music. If you made a file called music.html instead, the address would be the uglier /music.html.

Always ask for the home page link at the same time. If nothing links to your new page, nobody can find it.

6. Things you can ask for

Copy these and change the details to whatever you want. The trick is to say what you want, not how to do it.

Easy ones to start with

Change the title on the home page to my full name.

A good first one. Small, and easy to check.

Add a short paragraph about me under the title on the home page.

Add a link to my Instagram at the bottom of the home page.

Bigger ones

Add a page at /about with a few paragraphs about me, and link to it from the home page.

Change the colours of the whole site to blue and grey. Do it in style.css so every page changes at once.

All the colours live in one place at the top of style.css. Change them there and every page updates.

Add a photo to the home page. I’ll put the picture in the folder first.

Asking questions instead of making changes

Explain what’s in this folder, like I’ve never seen it before.

Handy when you come back after a few months and forgot everything.

Show me what I’ve changed but haven’t published yet.

Ones that don’t work

These don’t work because they’re too vague. The tool has to guess, and it usually guesses something you didn’t want:

“Make it better.” — Better how? Say what you don’t like.
“Fix the website.” — Fix what? Say what looks wrong.
“Add stuff to the page.” — Which page? What stuff?

7. If something breaks

You can’t really break this. Every old version is saved, so the site can always be put back. The worst that happens is the page looks weird for a few minutes.

The page looks wrong or empty. Ask:

The home page looks broken. Can you check what I changed and fix it?

You want to undo what you just did. Ask:

Undo my last change and put the site back how it was.

The website isn’t updating. Wait two minutes, then hold Shift and click reload. If it’s still old, ask:

Did my last change actually get published? Check and tell me what happened.

You got an error you don’t understand. Copy the whole thing and paste it to your tool, then ask what it means. Paste the exact words — don’t retype it or shorten it. The exact words are the useful part.

One rule. Read what the tool says it’s going to do before you say yes. It’s usually right, but it’s your website. Saying “no, do it this way instead” is a totally normal thing to do.

Stuck?

If something isn’t working, or you don’t understand a step, or you just want help figuring out what to build — ask Uncle Jimmy.
