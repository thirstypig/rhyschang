How to run this site

Everything you need to set up, change, and publish this website yourself. You don’t need to know how to code. You need to be able to type and to read carefully.

Two tools, two columns. This guide covers Claude Code and Codex. They do the same job. Pick one and follow only its column — Claude Code is on the left, Codex on the right. On a phone the columns stack, so look for the coloured label at the top of each box to know which one you’re reading.

1. What this site actually is

Three things work together. It helps to know what each one does before you touch anything.

The files. This website is a folder of files on a computer. Each page is one file. The page you’re reading right now is a file called howto/index.html. That’s it — there’s no magic.

GitHub. A website that stores those files and keeps a history of every change ever made. The copy lives at github.com/thirstypig/rhyschang. Because it keeps history, nothing you do is permanent. Anything can be undone.

GitHub Pages. A free service that takes those files and puts them on the internet at rhyschang.com. Whenever the files on GitHub change, it rebuilds the site automatically, usually in under a minute.

So the whole job is: change a file → send it to GitHub → wait a minute. Every instruction below is a version of those three steps.

2. One-time setup

You only do this section once, ever. It’s the longest part. After this, making a change takes about two minutes.

Step 1

Get a GitHub account and access to the site

Go to github.com/signup and make an account. You’ll need an email address you can check, because they send you a code.

Then tell James your GitHub username. He’ll invite you to the repository (that’s the word for the folder of files). You’ll get an email with an Accept invitation button. Click it. Without this you can read the files but not change them.

Step 2

Open the Terminal

The Terminal is an app where you type commands instead of clicking buttons. It looks intimidating and isn’t.

On a Mac: press Command and Space together, type Terminal, press Enter. A window with a blinking cursor opens. On Windows, search for Terminal in the Start menu.

From here on, “type this” means: type it into that window and press Enter.

Step 3

Install your tool

Both tools need a program called Node.js first. Get it from nodejs.org — download the version it recommends and run the installer like any other app. Then come back to the Terminal and install your tool:

Claude Code

npm install -g @anthropic-ai/claude-code

Official instructions, if that command ever changes: docs.claude.com

Codex

npm install -g @openai/codex

Official instructions, if that command ever changes: developers.openai.com

If you see a wall of red text mentioning permission denied or EACCES, the install was blocked rather than broken. Copy the whole message, paste it into a search engine or ask an adult — it’s a common, fixable setup problem, not something you did wrong.

Step 4

Sign in

Start your tool for the first time. It will open a browser window and ask you to log in. Each tool needs its own paid account — Claude Code needs a Claude plan, Codex needs a ChatGPT plan.

Claude Code

claude

Follow the sign-in prompts with your Claude account.

Codex

codex

Follow the sign-in prompts with your ChatGPT account.

Step 5

Copy the site onto your computer

Type these two lines, one at a time:

cd ~/Documents
git clone https://github.com/thirstypig/rhyschang.git

The first line moves you into your Documents folder. The second downloads the whole site into a new folder called rhyschang.

Now go into it. You’ll type this line every time you sit down to work on the site:

cd ~/Documents/rhyschang

Setup done. You never have to do section 2 again.

3. Making your first change

Let’s change one word and put it on the internet.

Step 1

Go to the folder and start your tool

Claude Code

cd ~/Documents/rhyschang
claude

Codex

cd ~/Documents/rhyschang
codex

Starting the tool inside the folder matters. That’s how it knows which files you mean.

Step 2

Ask for the change in plain English

Type this and press Enter. Same words for either tool:

On the home page, change the line that says “This site is just getting started” to say something about me instead.

The tool will find the file, show you what it wants to change, and ask permission. Read what it’s proposing. If it looks right, say yes.

Step 3

Publish it

The change is only on your computer so far. To put it on the internet, ask:

Save this change and publish it to the website.

The tool handles the technical steps. Wait about a minute, then open rhyschang.com in a browser. Your change is live.

Don’t panic if it looks unchanged. Browsers keep old copies of pages. Hold Shift and click reload to force a fresh one. If it’s still old, wait another minute — the site takes a moment to rebuild.

4. What just happened

Three things happened when you said “publish”. You don’t need to memorise these, but knowing the words makes error messages readable.

Commit. Your change got saved as a labelled snapshot, with a note about what changed. The full history is kept, so you can always go back.

Push. That snapshot got uploaded from your computer to GitHub.

Build. GitHub noticed the new files and rebuilt the website. This is the part that takes about a minute.

When something goes wrong, it’s almost always one of these three, and the error message will name which one.

5. Adding a new page

Say you want rhyschang.com/music. Just ask:

Add a new page at /music. Match the style of the existing pages, and put a link to it on the home page.

Behind the scenes it creates a folder called music with a file called index.html inside it. That’s the trick to clean web addresses: a folder named music containing index.html becomes /music. If you made a file called music.html instead, the address would be the uglier /music.html.

Always ask for the home page link in the same breath. A page nobody can click to is a page nobody will find.

6. Prompts that work

Copy these and change the details. The pattern that works is say what you want, not how to do it.

Easy

Change the title on the home page to my full name.

Good first one. Small, obvious, easy to check.

Add a short paragraph about me under the title on the home page.

Add a link to my Instagram at the bottom of the home page.

Bigger

Add a page at /about with a few paragraphs about me, and link to it from the home page.

Make the whole site use a different colour scheme — something darker. Change it in style.css so every page updates at once.

Colours live in one place at the top of style.css. Change them there, not page by page.

Add a photo to the home page. I’ll put the image file in the folder first.

Asking questions instead of changes

Explain what this repository contains, like I’ve never seen it before.

Great when you come back after a few months.

Show me what I changed but haven’t published yet.

Prompts that go badly

These fail because they’re vague, so the tool has to guess — and it guesses something you didn’t want:

“Make it better.” — Better how? Say what bothers you.
“Fix the website.” — Fix what? Describe what you see that’s wrong.
“Add stuff to the page.” — Which page, and what stuff?

7. When something breaks

Nothing here is dangerous. The history is kept, the site can always be put back. The worst realistic outcome is a broken-looking page for a few minutes.

The page looks wrong or empty. Ask your tool:

The home page looks broken. Can you check what I changed and fix it?

You want to undo the last thing you did.

Undo my last change and put the site back how it was.

The site isn’t updating. Wait two minutes and hard-reload (Shift + reload). If it’s still stale, the publish step probably didn’t finish — ask:

Did my last change actually get published? Check and tell me what happened.

An error message you don’t understand. Paste it straight into your tool and ask what it means. Don’t retype it or summarise it — the exact text is the useful part.

The one rule. Read what the tool proposes before you say yes. It’s usually right, but it’s your site. Saying “no, do it this way instead” is a normal part of the conversation, not a failure.
